===========================
 Handling floating windows
===========================

== Goals ==

  1. Ability to open floating windows
  2. Have the ability to have child floating windows (eg: tooltip
     inside a tooltip)
  3. open them arbitrarily
  4. Proper handling of them, eg closing tooltips when their parent
     tooltip is no longer hovered.

== 1 Implementation ==

1.1 Data Structure

  interface FloatingObject {
    obj: RenderObject
    type: "tooltip" | "non-tooltip"
    domNode: DelphiNode
    sourceNode: DelphiNode
    childNode: FloatingObject
    parentNode: FloatingObject
  }
  Notes:
    - 'domNode' represents the root DOM object of the floating window
    - 'sourceNode' represents the root's parent, in effect. For example
      the source node of a tooltip is the element that was hovered over
      to cause the tooltip to be spawned.

  interface FloatingObjectManager {
    windows: FloatingObject[]

    tick(): void
  }
  Notes:
    - Windows is simply a list of windows, each of which is ticked and
      calculated if it should remain open.


1.2 Opening
  When a floating window is created, it can either be a root window or
  a child of another floating window.
  Floating windows behave differently when either root or child objects.
  If a floating window belongs to another floating window, its
  visibility and interactability depend on its parent also being
  visible.

1.3 Behaviour
  Floating windows behave differently depending on the context in which
  they were opened.

  1.3.1 Tooltips
    Depending on the tooltip parameters, the floating window behaves
    differently.

    'cursor-sticky' mode tooltip:
      The tooltip window follows the cursor and additional child nodes
      cannot be opened.
    'cursor', 'below', 'above', 'left', 'right':
      Behave as regular floating windows.

    For all types of tooltip floating windows, if the tooltip'ed
    element itself is unhovered, the entire tree is eradicated.

  1.3.2 Everything else:
    Once opened, floating windows can be closed by clicking anywhere
    except on the floating window itself. This only applies to
    non-tooltip windows.

  1.3.3 Cursor interaction handling
    This section really only matters for tooltips

    When a node hovered over which has a tooltip, the tooltip logic is
    executed, assume the tooltip floating window has appeared. The way
    cursor interactions are handled must accommodate the newly appeared
    window.

    The window must not be closed if either it, its element or any of
    its child objects are currently hovered. This needs to be applied
    separately down the entire window linked list.

    When assessing if a floating tooltip should be closed, the context
    of the floating window should be taken into account. A tooltip must
    be closed only if the tooltip itself isn't hovered and its parent
    isn't hovered and any child objects are not hovered.

1.4 Closing
  When a node is closed, its child objects have to be recursively
  closed as well.
